# 中文最终可执行 Task 文档模板

用于方案明确、事实清楚、待确认事项已全部解决、任务已足够细化后的执行文档。生成文档时删除所有模板提示，不保留空占位符；没有内容时写“无”“未开始”“未运行”。

最终文档是执行控制面，只保留执行所需的事实、决策、规则、任务和验证。最终文档不得保留选择性实施分支；每个候选任务、优化项、清理项、兼容规则和验证扩展必须已经裁定为纳入当前计划、明确不纳入当前计划、客观阻塞或待确认。存在待确认事项时不得使用本模板。

```md
# <子系统或任务名称> 执行任务文档

## 0. 执行控制台

| 计划过期触发 | <具体文件、模块、接口、配置、文档、需求、运行状态或用户决定变化后必须重新检查本文> |
| 文档模式 | <确定的文档模式> |

## 0.1 状态口径

| 类别 | 口径 |
| --- | --- |
| 状态 | 未开始 / 进行中 / 部分完成 / 阻塞 / 已完成 / 不再执行；“当前状态”和任务“状态”只能写这些值，解释写入状态说明或后续备注 |
| 任务量 | S：局部小改；M：单模块或相邻模块；L：跨模块、核心路径或迁移类任务 |
| 上下文风险 | 低：局部即可；中：需多文件或历史决定；高：核心路径、跨模块、迁移、排障或大量证据 |

## 0.2 全局执行规则

- 本文是持续维护的实施指南。后续执行默认只读取本文，不加载生成本文的 skill 或前序对话。
- 指定任务执行：先检查任务状态、前置任务、阻塞条件、解除条件和当前工作区证据；存在未解除阻塞时先说明阻塞，不得直接绕过。
- 任务完成后必须更新任务状态、实际完成、验证记录、后续备注、当前状态、状态说明、总体进度、下一步任务和文档更新记录。
- 状态输出：用户要求状态时，结合本文和当前工作区证据列出所有任务，使用表格 `任务 / 标题 / 文档状态 / 实际状态判断 / 阻塞项 / 下一步动作`，并标出过期、不一致或无法验证的状态。
- 完成情况检查：先对照本文和工作区列出未完成、错误实现、缺失验证、计划偏差、文档过期和可优化项；结果先给用户确认；未经确认，不得写入检查记录或追加任务。
- 任务编号不得重排；新增任务追加到末尾；不再执行的任务保留编号和原因。实现偏离计划时，更新本文以匹配已落地代码。
- 本文不得保留选择性实施分支。执行中发现未裁定的实现、清理、兼容或验证选择时，先标记相关任务为阻塞并请求用户裁定，不得自行执行。

## 0.3 全局验证规则

- 验证记录只能写实际运行过的命令、测试或检查；未运行必须写明原因。
- 如果证据基线涉及的代码、文档、配置、接口或用户要求明显变化，先更新证据、方案和任务，或把相关任务标记为阻塞。
- 按任务类型触发验证：代码任务、发布或包边界任务、CLI/UI 行为任务、数据安全任务、迁移任务、性能任务、文档任务和运维任务分别列出需要运行的检查；不适用的验证必须写明原因。
- 任务级验证可继承本节；任务有特殊验证要求时在任务内单独写明。

## 0.4 全局禁止项

- 不得绕过未解除阻塞。
- 不得把未运行的验证写成已通过。
- 不得删除历史任务编号或重排任务。
- 不得保留已经失效的状态描述、验证描述或下一步描述。
- 不得在目标方案、任务步骤、验收标准或后续备注中保留选择性、非裁定性表述；客观失败处理和阻塞解除条件除外。
```
